# Progress-backed passwordless return qualification

This continues Phase 2 under the clarified laboratory requirement. Progress-backed
return is an allowed path. No participant password, email, identifying field or
new experiment marker is required. The existing account/experiment rules remain
unchanged; genuine Prolific entry remains separate.

## Fixture and custody

Use staging2 only, the existing operator sign-in and a fresh source-generated
namespace. Preserve the accepted selected/reset/session/lifetime evidence. One
ordinary synthetic learner supplies the settings/performance/publication positive
baselines. One separately recorded pseudonymous participant starts with saved
progress and no password, email, experiment flag or stored target. Two new synthetic
TDF roots provide the assigned/other-target baselines. No real learner is used.

`passwordlessFixturesV2.mjs` plans six insert-only records: participant account,
two roots, participant/foreign progress and one foreign history. Preflight rejects
ID, username and target collisions and validates the actual staging2 Mongo/ROOT_URL
metadata and native learner ownership. Only the new learner's verification flag
is set for its baseline. Keep the ID/name/creator/time ownership manifest before
mutation. Missing experiment markers are not substituted for ownership checks.

Use one environment-scoped window and private per-run evidence. The remote
operator controller must hold staging2's existing qualification lock during the
window, check the same container/image and retain a recovery marker if the owner
is interrupted. A stale marker requires named recovery, never automatic takeover.
No background service, management port, broader role or provider credential is
needed. Transfer only the committed public helper source, privately; do not reuse
an old completed qualification directory or a stale container tool copy.

## Observe and clean

The browser adapter requires a live lease check before acquisition, before token
issuance and after cleanup. It owns and closes its private contexts, validates
the bound identities, requires the five positive baselines, resumes the recorded
participant, checks access/denials, and verifies identity and saved progress after
reload. Disclosure capture is bounded; stalled/failed capture is ERROR. Only an
exact own-session native resume handoff is excluded from unintended disclosure.
Keep capabilities and raw wire/mail data in private transient input, never evidence.

Remove only the five planned data rows through the datastore owner. Remove the
participant and new learner through the existing admin-guarded deletion method,
after exact ownership checks; confirm absence independently. Interrupted insertion
must recover the same namespace, including uncertain native account creation.
Keep the failed result and recovery manifest until all owned access/data is absent.
The local fixture/browser tests are preparation, not live cleanup acceptance.

## Report boundary

The historical catalog-v1 `experiment-flag` title does not express the laboratory
requirement. The new acquisition records experiment eligibility from an explicit
marker or verified owned progress; it must not publish that as proof of a literal
flag in the old catalog. Its qualification tag requires the planned next catalog
version with corrected claim/title and source-qualified comparison/lifetime proof
references. Keep catalog v1 immutable and the active selected-only producer's
remaining protocol controls ERROR until that coordinated qualification passes.

No production acceptance, paid provider call, new credential or app deployment is
implied. Reserve supported Meteor invocations only in the standing ledger.
